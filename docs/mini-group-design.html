拾传 Mini
一个群，一个随手能用的小窗。

平时留在屏幕边缘。文件拖过来，小窗展开；松手发到这个群，其他设备收到后直接拿走。

Group 的含义已经确认：类似 QQ 群或微信群的共享会话。每个群有独立成员、消息、文件、邀请码和窗口；一个设备可以同时加入多个群。切换或创建群不会把当前群窗口变成另一个群。

2026-10-04：已选方案实施

用户选定多人文件传输会话与小半球方案。当前桌面源码已更新为蓝白会话、成员头像、紧凑文件卡与更多菜单；侧边收起为12×24半球，顶部收起为24×12半球，顶部定位于菜单栏下方的可用工作区。新窗口默认340×470，旧窗口保留其已保存尺寸。

支持左、右、顶部松手吸附，小半球可直接拖出，悬停约180ms展开，离开约800ms收起。透明窗口通过右下角把手缩放。已增加三边拖出、透明像素、自定义缩放和多群回归检查；以下早期24×88边签描述为调研历史，实际行为以此节与README为准。

桌面交互参数

以下是拾传当前实现的初值，不是竞品公布的参数：拖动5px后开始移动；靠近左右边缘24px内显示「松手贴边」；松手吸附动画180ms；悬停250ms展开；离开800ms收起。拖动时直接跟随指针，不做缓动追赶。聊天内容在展开、收起时保持固定宽度，窗口边界负责裁切，避免反复换行。

指针仍按住时不触发吸附，用户可以穿过显示器接缝。点击图钉保持展开；文件进入边签即开始展开。边签命中范围就是实际24px窗口，不用覆盖整条屏幕边缘的透明窗口。

发送前确认目标群与文件。
  1. 先接新群协议：手机当前仍使用旧版收件箱连接地址。需要统一设备身份、多群持久化、6位邀请码申请和审批、断线重连；先确保手机能进桌面端的群。
  2. 系统分享进入：相册/文件管理器/浏览器 → 分享 → 拾传 → 最近群 → 确认内容 → 发送。App内提供照片、文件与文字入口，保持完整替代路径。
  3. 文件卡片操作：点击预览，提供明确的保存与分享按钮；长按多选。每个文件拥有进度和重试，避免全局busy锁住整个界面。
  4. 顺应系统手势：左右边缘保留系统返回，底部适配安全区与键盘；iPad可后续做双栏和跨应用拖放。参考Android手势规范和Apple拖放规范。

原生接入选择：项目使用Expo 57。expo-sharing 57已有实验性接收系统分享能力，可以先做Android验证；官方明确提示其iOS实现会由分享扩展打开主App，此方式未获Apple正式支持。iOS正式方案应评估原生Share Extension，在扩展中选择群，借助App Group共享文件；较长传输参考Apple扩展与后台传输机制。仍需真机、局域网权限和后台生命周期验证。

本轮验证边界

单元测试覆盖按住不吸附、松手提交、边签拖出、取消、动画中断、图钉和减少动态效果。Electron交互检查使用真实窗口与渲染器指针事件，屏幕指针坐标受控模拟；不等于Mac/Windows物理鼠标、多屏混合DPI和系统文件拖放的实测。当前没有产出新的手机安装包。

群聊与窗口

  • 首次启动默认建立「我的设备」。可新建「工作资料」「家里」「临时交换」等群。
  • 一个群对应一个可独立移动、缩放、固定和贴边的小窗。同一个群重复打开时唤回原窗口，避免出现重复会话。
  • 群名下拉列出已加入的群，点击会打开或聚焦对应独立窗口。菜单中放「新建群聊」「输入邀请码加入」「本群设备」「邀请设备」。
  • 发到群里的文字和文件只进入该群。同一台电脑可以加入多个群；移出一个群不影响其他群。
  • 群的稳定 ID 与可修改名称分离，设备离线仍保留在成员列表。

小窗的最小结构

区域设计
尺寸默认约320×420；最小280×340。使用系统逻辑像素，保留缩放与位置，不把文字随窗口比例压小。
标题栏一行：群图标、群名下拉、固定展开、收起到边缘。标题空白处可拖动窗口。
设备状态紧凑一行「3台设备 · 2在线」。点击查看成员，离线成员显示等待自动重连。
内容短文字气泡、紧凑文件卡。文件显示名称、大小、来源、接收状态；完成后可直接拖出。
输入默认单行，左侧加号选择文件，Enter发送；占位文字「发到工作资料…」明确发送目标。
视觉灰白背景、细分隔线、系统字体、少量绿色用于发送/完成。无常驻侧栏，功能配置收进群菜单。

悬浮与贴边规则

悬浮小窗 → 拖到左右边缘或点击收起 → 群边签 → 文件拖入感应区 → 展开 → 松手发送

  • 每群一个24×88的直边边签，保留群简称；未读提示作为后续增强。多个边签排列、不互相覆盖，完整群名可通过悬停查看。
  • 文件进入边签区域立即展开；普通鼠标停留约250毫秒展开。展开/收起动画约180毫秒，遵循系统减少动态效果设置。
  • 临时展开后，鼠标离开约800毫秒收起；输入、选字、群菜单、邀请审批、拖入或拖出文件期间保持展开。
  • 「固定展开」让小窗持续悬浮。收到文件时边签提示新内容，默认不抢焦点弹出大窗口。
  • 收起只隐藏界面，传输继续。菜单栏/托盘保留恢复群窗口与退出应用的入口。
  • 避免覆盖系统热角和菜单栏/Dock；多屏分别记录停靠边与位置。拔掉显示器后把窗口移回可见屏幕。

邀请码与设备记忆

群菜单「邀请设备」 → 482 916 → 新设备输入 → 群内设备确认 → 永久记住该设备与群

  • 邀请码为6位数字，分成两段展示，5分钟有效、单次使用；过期可重新生成。
  • 输入邀请码只是申请入群。已有可信成员确认设备名称后，新设备才获得长期群凭据。
  • 重启后恢复已加入的群、设备、窗口位置、消息和已接收文件。IP变化时通过局域网发现重新定位，不要求重新配对。
  • 保存的是设备身份和群关系，不只是一条带 IP 的网址。离线与未配对必须是两个不同状态。
  • 第一阶段邀请码用于同一局域网。跨网络找设备需要另行增加协调/中继服务，不能靠缩短现有 URL 实现。

发送与异常状态

  • 拖入时覆盖层明确写出「松开，发到工作资料」；送达记录留在这个群窗口。
  • 接收中显示进度，文件完整落盘后才允许原生拖出。不能显示一个尚不可用的“可拖出”状态。
  • 显示「已发送至收件箱」与「某设备已接收」时应有对应的真实证据；不能把服务端上传完成当作所有群成员已收到。
  • 网络断开时保留群和内容，显示等待重新连接。第一阶段继续采用每群托管电脑架构：托管机离线时明确提示等待它上线，不暗示任意设备均能中继。
  • 选择文件、改变群窗口位置或收起窗口，都不改变已经开始上传的目标群。

实现与验收

保留现有文件流式收发、SHA-256校验和原生拖出能力。将单一收件箱扩展成多个独立群服务；增加群注册表、设备发现、短码申请和审批；桌面按群维护独立窗口和缓存。Electron 已提供置顶、尺寸与多屏信息接口，贴边触发使用小范围可接收拖拽的原生窗口；全局外部拖拽检测、全屏和多显示器差异需要分别实测。参考 BrowserWindow、screen。

  1. 两个群同时打开：A群消息和文件不会出现在B群，B群窗口位置不随A变化。
  2. 创建/加入群后得到独立小窗；重启后仍有原有群、成员、记录和固定状态。
  3. 6位码申请、批准、拒绝、过期和限流均有真实后端结果。
  4. IP地址改变后重新发现可信群服务；伪造发现公告不能诱导发送长期凭据。
  5. 两群贴边互不覆盖；拖入到指定边签后正确发到该群；从接收卡拖到桌面得到真实文件。
  6. 320×420与280×340下标题、消息、输入和审批均可操作。Mac/Windows分别验证系统拖放与贴边行为。

手机端沿用相同群与设备关系，使用群列表进入各自会话和系统分享入口。悬浮、贴边、多窗口是桌面端的主要交互。
