拾传 PickDrop — Linux TUI 视觉方案调研
日期：2026-10-05
状态：视觉概念候选，尚未修改 TUI 业务代码。图中的演示数据不是实际连接状态。
协作：TUI 研究员核验官方案例；美术/UI 设计师提出布局与色彩；主线程检查实现并使用内置 image_gen 生图。

现状与依据
当前 apps/tui/ui.js 使用 Ink 6.3.1 / React 19.2.3。主体是单列消息，宽度随终端铺满。发送者、时间、文件大小与状态的层级弱；群、设备与传输任务没有稳定的空间位置；长链接影响扫描。
已有 snapshot 提供 groups、state.devices、messages、transfers、requests。界面可重组这些数据，不需要先重做传输协议。设备名单的具体展示字段仍需在实施时确认。
截图的蓝色纹理可能来自终端背景，不能仅凭截图确定由应用绘制；当前 ui.js 没有指定全屏背景色。

研究来源（官方项目）
1. superfile — https://superfile.dev/getting-started/tutorial/
   多分区、侧栏、任务与元数据，适合三栏工作台的信息架构。
2. Posting — https://posting.sh/guide/navigation/
   集合侧栏、主工作区与焦点导航，适合会话为主的双栏布局。
3. termscp — https://termscp.rs/
   最接近文件传输的参考；借鉴源/目标语义、路径与操作提示，不照搬远程文件管理器。
4. Yazi — https://yazi-rs.github.io/docs/quick-start/
   紧凑列表、详情按需与任务展示，适合低边框高密度方向。
5. lazygit — https://github.com/jesseduffield/lazygit/blob/master/docs/Config.md?plain=1
   主题与边框配置、聚焦当前面板，帮助控制终端的色彩与边框噪声。
上述布局建议是基于参考项目与 PickDrop 代码提出的原创组合，并非声称复制其完整交互。

方案
A 青绿工作台：深石墨底，青绿焦点；左群列表、中会话、右设备及传输。适合宽屏与常驻使用，最推荐。
B 靛紫会话台：左群与设备，右大会话；任务收进输入区上方。少边框、较舒展，适合日常聊天与传文件。
C 纸白控制台：米白与墨绿；无固定侧栏，顶部群导航，时间/发送者/内容列对齐。适合浅色终端和较高信息密度。

统一约束
- 实色背景、等宽网格、字符边框与块状进度；避免阴影、玻璃、GUI 头像与气泡。
- 文件与文字保留共同时间线，不拆成互不关联的管理界面。
- “已存入群主机”不等于所有设备已收到；下载完成必须关联真实任务结果。
- 不画为既有能力的搜索、文件夹传输、已读、暂停续传、加密锁或云同步。
- 现有 Ctrl+P 菜单 / Ctrl+O 发文件 / Ctrl+G 切群 / Esc 返回 / Ctrl+C 退出保留。
- 建议 140 列以上显示第三栏；100–139 列双栏；不足 100 列收起侧栏。断点为待实际终端验证的设计建议。
- 中文按显示列宽裁切，长文件名保留扩展名，长 URL 限行；状态使用文字和颜色共同表达。
- 概念图仅供方向选择；字符逐格对齐、所有中文与真实终端效果以实施验收为准。
