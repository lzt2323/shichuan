# 拾传 v0.3.5 · 群连接恢复与设备管理

## 本版变化

- 桌面成员面板支持移除设备，撤销该设备凭据、连接、在途传输和旧审批票据；普通成员可退出群或仅在本机忘记群，历史聊天和文件保留。
- 自动网络模式跟随物理网卡 DHCP 地址变化，主机优先复用上次服务端口；端口被占用时可通过发现更新地址。
- Android 前台持续发现已加入群并自动恢复连接，监听网络变化，支持新版 NSD 服务信息更新、UDP 发现及有上限的当前私有子网目录探测。桌面附近群列表实时更新。
- 候选新地址通过主机身份挑战后才接收凭据；连接超时和失败原因可见，保留群配置与草稿，授权撤销后停止无效重试。
- 文件草稿绑定群、主机和设备凭据；主机地址变化后验证新地址再发送，并保护并发重新配对时的新旧凭据。
- 修复 Android UDP 端口绑定失败时的 socket 释放路径；原生构建正确上报 Gradle 错误。

## 下载与升级

| 系统 | 安装包 |
| --- | --- |
| Mac Apple 芯片 | `PickDrop-0.3.5-Mac-AppleSilicon.zip` |
| Windows x64 | `PickDrop-0.3.5-Windows.exe` |
| Android ARM64 | `PickDrop-0.3.5-Android-arm64-preview.apk` |
| Linux x64 终端版 | `PickDrop-0.3.5-Linux-x64-TUI.tar.gz` |
| Linux ARM64 终端版 | `PickDrop-0.3.5-Linux-arm64-TUI.tar.gz` |

各端请同步升级。桌面退出旧版后替换应用，保留用户数据目录。Android 内测版 versionCode 升至 305，沿用独立包名与测试签名，可覆盖安装上一版内测 APK，保留应用数据。Linux 先执行 `pickdrop stop`，解压新版后执行 `./pickdrop install` 和 `pickdrop open`。

新建群使用每设备独立凭据。旧群保持原协议，托管电脑首次启用移除功能时需确认升级设备授权；升级后旧成员需重新批准加入一次，原群 ID、聊天及文件保留。旧版客户端无法加入新版授权群。托管电脑不能退出或忘记正在托管的群。

所有安装包来自同一标签，附 `SHA256SUMS.txt` 与 `ANDROID-BUILD.txt`。

## 验证与边界

修复提交的 160 项自动化测试、源码检查、手机类型检查、iOS/Android 资源导出、桌面双群与成员管理 smoke、桌面视觉及审批 smoke 已通过；macOS、Windows、Android 和 Linux 两种架构构建已通过。发布流程会对本版标签再次检查并构建，安装包齐备后统一发布。

Windows 与 Android 真机跨设备网络验收仍待执行；窗口拖动 smoke 在原始代码和修复代码中均存在当前环境下的鼠标捕获失败，已记录。访客网络隔离或防火墙阻断仍可能影响发现与连接，发现回退不会绕过设备隔离。

继续作为内测版发布：桌面包未正式签名或 macOS 公证，Android 使用公开测试证书与独立内测包名，不包含 iOS IPA。仅适合可信局域网，HTTP/WebSocket 尚无 TLS 或端到端加密。
